# Audit record, 11 November 2026

An independent read-only audit of the README, the report PDF, the CSV, the R script and the package was run on commit 3a87071. The CSV, the R script, the figures and the PDF were not changed. The commits that followed correct the README and the package import only.

## Findings

| Finding | Evidence | Status |
| :--- | :--- | :--- |
| The borehole series has no source | The `borehole_piezometric_mm` column has no provider, station list, coordinates or conversion code anywhere in the repository. The CSV entered in one bulk upload (c93f38f) | Validation claim withdrawn in the README |
| The comparison behaves like added noise | `residual_error_mm` equals `gws_anomaly` minus the borehole column exactly. RMSE 7.43 mm, NSE 0.966 and KGE 0.947 reproduce, but the residual has lag-1 autocorrelation 0.127 (the satellite series has 0.98), Shapiro-Wilk p = 0.62 and skew 0.007 | This is a statistical signature, not proof the column is synthetic |
| The time axis is not monthly | The steps are exactly 0.0862 years (a linear spacing), not calendar months. The 2017 to 2018 GRACE gap has full seasonal values and no missing rows, and the residual spread inside the gap equals the spread outside it | Not verified |
| The seasonal phase contradicts the report | After detrending, all four storage columns peak in May and bottom out in October to November. Figure 5 and the README claim August (soil moisture) and October (groundwater), and a May soil-moisture peak is wrong for the Sahel | Lag claim marked not reproduced |
| Headline numbers do not match the data | The trend is -5.67 mm per year (OLS) and -5.70 (Theil-Sen), and Figure 3's legend says -5.67. The README and report gave -5.84 and 1.97 km³ per year (-5.67 gives 1.94). The report quotes Shapiro-Wilk 0.982; the CSV gives 0.9956 | README corrected; the PDF is not |
| Surface water source | GLDAS-2.1 Noah has no surface-water or lake storage term, yet the README says surface water came from GLDAS | Noted in the README |
| Autocorrelation ignored | The OLS p-value and the Mann-Kendall test assume independence while the detrended lag-1 autocorrelation is 0.88. The effective sample size is about 17.5 and the trend is still significant, but the report's claim of robustness to autocorrelation is not supported. The Mann-Kendall variance has no tie correction | README says so |
| Constant uncertainty | `gws_uncertainty` is 14.3837 mm in every row, and its source is not stated | Open |
| Scale claims | The Maiduguri hotspot and "artesian drawdown" are finer than GRACE resolves and cannot separate confined from unconfined storage. A specific yield of 0.052 is an unconfined value | README reworded |
| No code for several claims | The cross-spectral phase analysis, the drought index epochs, the rain-to-groundwater correlation, the stress index weights and the equipotential map were made in an external Colab that is not in the repository | Open |
| The package was broken | `__init__.py` imported a `metrics` module that does not exist, so the tests could not be collected | Fixed; 2 tests pass |

## Corrected in the commits that follow 3a87071

A status notice, the trend and volume figures, the hotspot and lag wording, the borehole comparison wording, the GLDAS note, and the package import.

## Open

- Real borehole records with a named source, and a validation re-run on them, are needed before any validation claim.
- The time series needs rebuilding from real GRACE and GRACE-FO data with the actual gap and the monthly dates.
- The PDF report repeats the corrected figures and the validation claims and has not been changed.
- `pyproject.toml` depends on `spatial-stats-core`, which nothing in the package imports, and that package has no `metrics` module either.
- Wording such as "thirty-year" for 2002 to 2025, "exceptional predictive skill" and "independent in-situ piezometric telemetry" remains in the PDF.

## Rebuild and second audit, 12 November 2026

The study was rebuilt from published gravity data (see the README). The first version is in `archive/withdrawn-v1/`. Six independent reviews of the rebuild (method, code, numbers and references, statistics, page, requirements) found the following, and each was addressed before publication.

| Finding | What changed |
| :--- | :--- |
| The level-4 unit first used is not the lake's sink: it drains into the terminal unit and misses part of the lake | The main area is now the level-3 unit, which holds the whole lake system; the level-4 unit is kept as a western sensitivity test and named as such |
| One straight line through a record that is flat until about 2018 and then rises steeply | Rates by period, a two-segment fit with its break range, and the full-record rate for three end dates |
| The bootstrap interval was too narrow and the autoregressive interval was mis-specified | Rates and intervals from generalised least squares with autoregressive errors that respect missing months |
| The spread across choices was larger than the stated interval | A table of rates for two gravity solutions, with and without the leakage correction, two soil models and two areas |
| Only one gravity solution | The GFZ RL06 solution added (not independent of COST-G) |
| The break sits near the gap between the missions | A test of the step between missions: not distinguishable from zero and in the wrong direction to explain the rise |
| Overclaims about soil depth, the lake being inside the area, G3P being the same data, and the first version | Reworded; G3P is described as built from an earlier release |
| Lake altimetry not mentioned | The paper says the Hydroweb series could not be reached |
| Page: distorted figures on phones, 391 tab stops on the map, chart without axis titles, legend or gap band, ocean cells shown as zero | Fixed; the map has one tab stop with arrow-key movement and a table alternative |
| Tests only checked outputs | Unit tests for the weights, the month matching, the rate and the two-segment fit, and a test that the paper build stops when a step is missing |

### Open

- No independent groundwater validation: no well records were available.
- Groundwater and surface water are not separated; lake altimetry could not be downloaded.
- Both gravity solutions come from the same processing chain; a solution from another centre (for example JPL mascons) was not added.
- Neither soil model was compared with soil-moisture observations.
- What caused the rise (rainfall, inflow, lake extent) was not analysed.
